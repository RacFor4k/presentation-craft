# Morph choreography

PowerPoint Morph — самый сильный нативный инструмент движения. Он же самый быстрый
способ сделать колоду, которая выглядит сломанной: чёрные провалы, двоящиеся заголовки,
объекты, летящие через текст.

**Правило:** Morph только там, где объект реально переходит между соседними слайдами
и движение объясняет связь. Все остальные стыки — fade.

## Что умеет Morph

- Двигает, масштабирует, вращает и перекрашивает **совпавшие** объекты.
- Меняет текст, если совпал текстовый блок; слова/буквы можно морфить отдельно.
- Не морфит графики (charts) — они кроссфейдятся.
- Работает между соседними слайдами; переход хранится на **входящем** слайде.

## Как PowerPoint находит пару

- Одинаковый тип: фигура → фигура, текст → текст, картинка → картинка.
- Одинаковое имя в `p:cNvPr@name`.
- Имена с префиксом `!!` заставляют 1:1-пару даже для разных фигур.
- Одно имя — один объект на слайде. Дубликат имени ломает пару.

В pptxgenjs:

```js
slide.addShape(pres.ShapeType.ellipse, {
  x: 1, y: 2, w: 1, h: 1,
  fill: { color: "FFFFFF" },
  objectName: "!!earth",       // одинаково на соседних слайдах
});
```

## Где Morph действительно нужен

- Формула переезжает и растёт; таблица встаёт на место легенды.
- Планета едет по оси от `r` к `2r`.
- Объект меняет масштаб, показывая отношение масс/расстояний.
- Один и тот же кадр панорамируется/зумируется (crop window), как камера.

## Где Morph вредит

- Слайды не имеют общих объектов. Morph сначала гасит старые, потом вводит новые —
  появляется **чёрный провал** на 0,3–0,5 с.
- Заголовок меняется полностью. В середине перехода видны два заголовка друг под
  другом. Если это не осознанный кроссфейд, используй fade или уникальные имена.
- Объект летит через текст, подпись или лицо.
- Morph стоит на каждом стыке «потому что можно». Движение перестаёт что-то значить.

## Черный провал и белая вспышка

| Симптом | Причина | Лечение |
|---|---|---|
| Чёрный кадр в середине | Нет общих объектов; Morph погасил старый слайд | Fade на этот стык |
| Белая вспышка | У слайда нет собственной заливки фона; при морфе проступает белый мастер | `slide.background = { color: "000000" }` на каждом слайде |
| Шапка исчезла | Полноэкранное фото добавлено после текста | Сначала фото, потом шапка/индекс/кредит |
| Два заголовка | Текстовые блоки совпали, текст разный | Уникальные имена или fade; не морфить заголовки |
| Земля обрезана | Картинка меньше/больше кадра или crop не тот | Пересчитать w/h и кроп; проверить в 16:9 |

## Длительность

- **Fade — 0,1 с.** Это быстрый монтаж, а не отдельный аттракцион.
- **Morph — 0,5 с** по умолчанию. Только там, где объект объясняет связь.
- 0,8–1,2 с — исключение для одного большого объекта с длинным путём, если
  пользователь явно просит медленнее. 1,2–1,7 с — старый медленный режим,
  заголовки и подписи успевают задвоиться; не использовать без просьбы.
- Одинаковая скорость для всех объектов: длинное расстояние = быстрый полёт.
  Ставь объекты так, чтобы путь был осмысленным.
- Если объект должен появиться из-за кадра, ставь его за кадром на том же
  расстоянии, с которого он должен войти.

## XML

Morph — расширение `p159` (2015/09), его надо обернуть в `mc:AlternateContent`
с fallback на fade. Transition живёт на входящем слайде, после `</p:clrMapOvr>`.

```xml
<mc:AlternateContent xmlns:mc="http://schemas.openxmlformats.org/markup-compatibility/2006">
  <mc:Choice xmlns:p14="http://schemas.microsoft.com/office/powerpoint/2010/main"
             xmlns:p159="http://schemas.microsoft.com/office/powerpoint/2015/09/main"
             Requires="p14 p159">
    <p:transition spd="fast" p14:dur="500" advClick="1">
      <p159:morph option="byObject"/>
    </p:transition>
  </mc:Choice>
  <mc:Fallback>
    <p:transition spd="fast" advClick="1"><p:fade/></p:transition>
  </mc:Fallback>
</mc:AlternateContent>
```

`option`: `byObject` (по умолчанию), `byWord`, `byChar`.
Fade-стык:

```xml
<mc:AlternateContent xmlns:mc="http://schemas.openxmlformats.org/markup-compatibility/2006">
  <mc:Choice xmlns:p14="http://schemas.microsoft.com/office/powerpoint/2010/main" Requires="p14">
    <p:transition spd="fast" p14:dur="100" advClick="1"><p:fade/></p:transition>
  </mc:Choice>
  <mc:Fallback>
    <p:transition spd="fast" advClick="1"><p:fade/></p:transition>
  </mc:Fallback>
</mc:AlternateContent>
```

`scripts/add_morph.py` делает это по списку:

```bash
python scripts/add_morph.py deck.pptx \
  --dur 500 \
  --fade-dur 100 \
  --fade 2,3,6,7,8,9,10,11
```

В примере Morph остаётся только на 3→4 и 4→5; остальные стыки — fade.

## Хореография «Тяготения»

- **3 → 4:** формула едет влево и растёт; Земля и Луна сжимаются в пару внизу;
  легенда превращается в таблицу четырёх величин.
- **4 → 5:** Земля и Луна растут; Луна едет от `r` к `2r`; формула уезжает вправо;
  таблица обратного квадрата появляется.
- **Остальное:** fade. У истории, Солнца, Сатурна, МКС и линзы нет общих объектов;
  Morph там давал чёрный провал.

## Проверка видео

Статика не показывает переход. Обязательно:

```bash
powershell -ExecutionPolicy Bypass -File scripts/render_video.ps1 \
  -Pptx deck.pptx -Out preview.mp4 -SlideSeconds 3 -Fps 30
```

Затем вытащи кадры:

```bash
ffmpeg -ss 2.4 -i preview.mp4 -frames:v 1 frame.png
```

Проверь:

- [ ] нет чёрного кадра в середине;
- [ ] нет белой вспышки;
- [ ] нет двух заголовков;
- [ ] объект не проходит через текст/подпись;
- [ ] Луна/планета действительно доезжает до конечной точки;
- [ ] финальный кадр совпадает со статикой слайда;
- [ ] fade 0,1 с, Morph 0,5 с; длиннее — только по просьбе.

Собери контакт-лист кадров каждые 0,1–0,2 с вокруг перехода и посмотри глазами.
Один удачный кадр ничего не доказывает; нужна вся дуга.

## Совместимость

- PowerPoint 2019/365 — Morph работает.
- Старые версии / Keynote / Google Slides — сработает `mc:Fallback` fade.
- PDF не сохраняет переходы; видео и PPTX — сохраняют.
